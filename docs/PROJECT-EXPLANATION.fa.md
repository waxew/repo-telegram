# توضیح کامل پروژه

## هدف

هدف پروژه این است که یک ربات مرکزی، «کارخانه‌ی فروشگاه تلگرامی» باشد. کاربر لازم نیست برای هر مشتری دوباره برنامه‌نویسی کند. او در BotFather ربات می‌سازد، توکن را یک‌بار به ربات‌ساز می‌دهد و همان کد مشترک، رفتار فروشگاه جدید را با تنظیمات و داده‌های مستقل اجرا می‌کند.

هر ربات مشتری هویت و توکن خودش را دارد، اما همه‌ی آن‌ها روی یک Cloudflare Worker اجرا می‌شوند. مسیر وبهوک هر فروشگاه یک UUID غیرقابل‌حدس دارد و درخواست‌های تلگرام با secret header مستقل کنترل می‌شوند.

## جریان اصلی

1. کاربر وارد ربات‌ساز مرکزی می‌شود.
2. گزینه «ساخت ربات فروشگاه» و سپس «برای خودم» یا «برای مشتری» را انتخاب می‌کند.
3. راهنمای ساخت ربات در BotFather نمایش داده می‌شود.
4. توکن ارسال‌شده ابتدا از نظر ساختار و بعد با `getMe` بررسی می‌شود.
5. توکن با AES-256-GCM رمز می‌شود؛ متن ساده‌ی آن در Supabase ذخیره نمی‌شود.
6. یک فروشگاه و یک وبهوک محرمانه ساخته و با `setWebhook` روی ربات مشتری ثبت می‌شود.
7. مالک وارد ربات جدید می‌شود، پنل مدیریت را باز می‌کند و دسته، محصول، پلن و تنظیمات مالی را می‌سازد.
8. مشتریان همان ربات، کالا می‌بینند، کیف پول شارژ می‌کنند و خرید انجام می‌دهند.

## زبان و ابزارها

### TypeScript

تمام منطق Worker با TypeScript نوشته شده است. حالت `strict` روشن است تا خطاهای null، نوع callback و داده‌ی JSON هنگام توسعه مشخص شوند.

### Telegram Bot API

به‌جای فریم‌ورک وابسته به یک توکن ثابت، یک Client کوچک مبتنی بر `fetch` نوشته شده است. دلیل این انتخاب، پویا بودن توکن صدها ربات مشتری است. متدهای استفاده‌شده شامل `getMe`، `setWebhook`، `sendMessage`، `sendPhoto`، `sendDocument`، `copyMessage`، `forwardMessage`، `getChatMember` و `answerCallbackQuery` هستند.

### Cloudflare Workers

وبهوک مرکزی، وبهوک‌های فروشگاه و کال‌بک زرین‌پال در یک Worker بدون سرور اجرا می‌شوند. Cron Trigger هر دقیقه یک بخش محدود از صف پیام همگانی را پردازش می‌کند تا وبهوک معمولی کند نشود.

### Supabase/PostgreSQL

Supabase داده‌ی اصلی را نگه می‌دارد. RLS روی همه‌ی جدول‌های جدید فعال است، نقش‌های عمومی مجوز ندارند و فقط کلید محرمانه‌ی بک‌اند به جدول‌ها دسترسی دارد. خرید و تأیید شارژ با تابع PostgreSQL و قفل ردیفی اجرا می‌شوند تا عملیات مالی اتمیک باشد.

### Web Crypto API

توکن‌های BotFather با AES-GCM و IV تصادفی رمز می‌شوند. secret وبهوک مشتری نیز به‌صورت SHA-256 ذخیره می‌شود، نه متن ساده.

### Vitest و GitHub Actions

تست‌ها ورودی اعداد فارسی، escape کردن HTML، رمزنگاری، tamper detection، ترتیب منوها و فایل بکاپ SQL را کنترل می‌کنند. Workflow هر Push و Pull Request را typecheck، test و dry-run build می‌کند.

## توضیح پوشه‌ها

- `src/index.ts`: ورودی Worker و Router امن تمام مسیرها
- `src/handlers/builder.ts`: حساب و ساخت ربات از طریق توکن BotFather
- `src/handlers/store.ts`: تشخیص فروشگاه، کاربر، مدیر، اشتراک و عضویت اجباری
- `src/handlers/customer.ts`: محصولات، کیف پول، خرید، سفارش و پشتیبانی
- `src/handlers/admin.ts`: تمام منوها و ویزاردهای مدیریت
- `src/lib/database.ts`: تنها محل اجرای Queryهای Supabase
- `src/lib/telegram.ts`: Wrapper مستقیم Telegram Bot API
- `src/lib/crypto.ts`: رمزنگاری توکن و اعتبارسنجی secret
- `src/lib/zarinpal.ts`: درخواست و Verify رسمی پرداخت
- `src/lib/broadcast.ts`: پردازش صف پیام گروهی
- `src/lib/backup.ts`: تولید SQL قابل بازیابی برای یک فروشگاه
- `src/ui/texts.ts`: تمام متن‌ها و برچسب دکمه‌ها
- `src/ui/keyboards.ts`: تمام چیدمان‌ها و رنگ دکمه‌ها
- `supabase/schema.sql`: جداول، ایندکس‌ها، RLS، مجوزها و توابع اتمیک

## نکته درباره کامنت‌ها

کدهای اجرایی و SQL توضیحات نزدیک به محل استفاده دارند تا خواننده بداند هر متغیر، شرط و Query برای چیست. کامنت‌های داخلی انگلیسی ساده‌اند تا نام فنی و کد در کنار هم قابل جست‌وجو باشند؛ این سند شرح فارسی همان ساختار است. JSON استاندارد کامنت را قبول نمی‌کند، بنابراین `package.json` و `tsconfig.json` عمداً بدون کامنت‌اند.
