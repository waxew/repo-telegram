# ربات فروشگاه‌ساز تلگرام

این مخزن یک سامانه‌ی چندفروشگاهی داخل تلگرام است: صاحب فروشگاه ابتدا در BotFather یک ربات می‌سازد، توکن را به ربات‌ساز مرکزی می‌دهد و سامانه برای آن ربات یک فروشگاه مستقل با وبهوک، کاربران، محصولات، سفارش‌ها و تنظیمات جداگانه ایجاد می‌کند.

ظاهر پروژه با رابط بومی تلگرام ساخته شده و ترتیب منوها، متن‌ها، ایموجی‌ها، کارت محصول، دکمه‌های آبی/سبز/قرمز و مراحل ویزارد از ویدئوی مرجع استخراج شده است. نمایش دقیق فونت و فاصله‌ها ممکن است در نسخه‌های Android، iOS و Desktop تلگرام کمی متفاوت باشد؛ چون رندر نهایی را خود برنامه‌ی تلگرام انجام می‌دهد.

## امکانات پیاده‌سازی‌شده

- اتصال ربات ساخته‌شده در BotFather، اعتبارسنجی توکن با `getMe` و ثبت خودکار وبهوک اختصاصی
- رمزنگاری AES-256-GCM توکن تمام ربات‌های مشتری قبل از ذخیره در دیتابیس
- جداسازی کامل اطلاعات هر فروشگاه با `shop_id`
- منوی فروشگاه شامل محصولات، جست‌وجو، حساب، شارژ، پیگیری سفارش، پشتیبانی و پنل مدیریت
- دسته‌بندی و محصول با نام فارسی/انگلیسی، توضیحات، حداکثر ۱۰ تصویر و چند پلن قیمت
- تحویل خودکار متن/عکس/ویدئو/صدا/فایل و تحویل دستی با دریافت اطلاعات مشتری
- کیف پول، دفترکل تراکنش، کد تخفیف، کد پیگیری و خرید اتمیک بدون امکان دوبار کسر موجودی
- پرداخت کارت‌به‌کارت با ارسال رسید و تأیید/رد مدیر
- درگاه واقعی زرین‌پال v4 با Request، Callback، Verify و جلوگیری از دوبار شارژ
- سیستم دعوت و پاداش اولین خرید زیرمجموعه
- آمار کاربران و فروش، فهرست کاربران، پیام مستقیم و صف پیام همگانی
- تنظیم عکس/متن شروع، پشتیبانی، کانال گزارش، کانال عضویت اجباری و ادمین دوم
- تغییر گروهی قیمت بر اساس کل فروشگاه، یک دسته یا یک محصول
- خروجی SQL مستقل از هر فروشگاه از داخل خود ربات
- تست خودکار TypeScript، رمزنگاری، ورودی فارسی، UI و فایل بکاپ

## فناوری‌ها

- TypeScript 7 و Telegram Bot API خام برای کنترل کامل ربات‌های پویا
- Cloudflare Workers و Cron Triggers برای وبهوک‌ها و ارسال‌های گروهی
- Supabase/PostgreSQL برای داده‌های ماندگار و تراکنش‌های مالی
- Web Crypto API برای رمزنگاری توکن‌ها
- Vitest برای تست واحد و GitHub Actions برای CI

## چرا دیتابیس خارجی لازم است؟

تلگرام فقط پیام و `file_id` فایل‌ها را نگه می‌دارد و API دیتابیس فروشگاه ارائه نمی‌کند. موجودی، سفارش، دسته‌بندی، محصول، وضعیت ویزارد، تنظیمات و ارتباط هر توکن با صاحب آن باید بیرون از تلگرام ذخیره شود. در این پروژه PostgreSQLِ Supabase منبع اصلی داده است؛ فایل‌های محصول با `file_id` خود تلگرام دوباره ارسال می‌شوند تا ذخیره‌سازی رسانه تکرار نشود.

## شروع سریع توسعه

```bash
npm install
cp .dev.vars.example .dev.vars
npm run secrets:generate
npm run dev
```

سپس مقادیر واقعی را در `.dev.vars` قرار دهید. این فایل در Git نادیده گرفته می‌شود و نباید منتشر شود.

برای اعتبارسنجی کامل:

```bash
npm run check
npm run build
```

## ساختار اصلی

```text
src/
  handlers/       منطق ربات‌ساز، فروشگاه، مشتری و مدیر
  lib/            دیتابیس، تلگرام، رمزنگاری، بکاپ، پخش پیام و زرین‌پال
  types/          قراردادهای داده و Telegram API
  ui/             تمام متن‌ها و کیبوردهای ظاهری
supabase/
  schema.sql      طرح کامل و توضیح‌دار PostgreSQL
  migrations/     مهاجرت‌های ثبت‌شده
assets/           طرح SVG قابل ویرایش برای تصویر شروع
scripts/          تولید رازها و ثبت وبهوک مرکزی
tests/            تست‌های خودکار
docs/             مستندات فارسی پروژه
```

تقریباً تمام بخش‌های TypeScript، SQL، SVG، Workflow و JSONC با توضیح خط‌به‌خط یا بلوک‌به‌بلوک نوشته شده‌اند. فایل‌های JSON استاندارد مانند `package.json` و `tsconfig.json` طبق قواعد JSON امکان کامنت ندارند؛ نقش تمام گزینه‌های آن‌ها در مستندات توضیح داده شده است.
